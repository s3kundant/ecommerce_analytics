# Olist E-commerce Analytics

Анализ данных бразильского маркетплейса Olist (~100k заказов за 2016–2018 гг.). 

Собрал пайплайн от сырых CSV до витрин и графиков: нормализовал схему, загрузил данные в PostgreSQL, через оконные функции посчитал продуктовые метрики (динамика выручки, когортный retention, stickiness) и сделал RFM-сегментацию на Python.

## Стек
* **База:** PostgreSQL 15 (Postgres.app)
* **Язык и библиотеки:** Python 3, pandas, SQLAlchemy, psycopg2, matplotlib, seaborn
* **Инструменты:** DBeaver, VS Code, Git

## Структура проекта
* `sql/` — DDL для создания таблиц и SQL-запросы метрик (DAU, MAU, когорты, stickiness).
* `scripts/load_olist_to_pg.py` — заливка очищенных CSV в PostgreSQL.
* `scripts/rfm_segmentation.py` — расчет RFM-скоров и сегментация клиентов.
* `scripts/visualize.py` — скрипт генерации графиков для отчета.
* `reports/` — выгруженные витрины (CSV) и диаграммы (`img/`).

## Главные инсайты по данным

### 1. Выручка и сезонность
* Самый крупный пик за всю историю — Черная пятница (24 ноября 2017).
* К середине 2018 года база стабилизировалась на уровне ~6.5–7k активных покупателей в месяц.

![Динамика выручки и MAU](reports/img/monthly_dynamics.png)

### 2. Когортный анализ (Retention)
* В данных Olist поле `customer_id` меняется с каждой новой покупкой, поэтому когорты считал строго по уникальному `customer_unique_id`.
* Удержание на 1-й месяц падает до **0.2–0.5%** по всем когортам. Причина: специфика маркетплейса — в основном продаются разовые товары длительного пользования (мебель, крупная техника), а механик повторного вовлечения практически нет (>97% клиентов покупают 1 раз).

![Когортный анализ](reports/img/cohort_retention_heatmap.png)

### 3. RFM-сегментация
Из-за того, что 97% пользователей совершили только одну покупку, дефолтный qcut по частоте (Frequency) не подходил — шкалу частоты настраивал вручную (1, 2, 3+ покупок).

* **50% выручки** приносят два сегмента: `Promising Whales` (крупные новички) и `Can't Lose Them` (бывшие VIP-покупатели).
* Сегмент `Can't Lose Them` принес более 3.4M реалов со средним чеком 430 реалов, но не покупает уже больше года. Это главная зона риска и кандидат на email/push-реактивацию.
* Сегмент `Lost / Hibernating` (27% пользователей) имеет средний чек всего 74 реала — запускать на них платный ретаргетинг невыгодно.

![RFM Сегменты](reports/img/rfm_segments.png)

## Запуск проекта
1. Установить зависимости: `pip install -r requirements.txt`
2. Создать файл `.env` с кредами от PostgreSQL (`DB_USER`, `DB_PASSWORD`, `DB_NAME`, `DB_HOST`, `DB_PORT`).
3. Накатить схему `sql/00_init_schema.sql` и запустить скрипт загрузки `python3 scripts/load_olist_to_pg.py`.
4. Сгенерировать графики: `python3 scripts/visualize.py`.
